# Protocol Deviations from `experiments/v3/PROTOCOL_v3.md` (ADR-0004 & ADR-0005)

Every deviation or specification choice between `experiments/v3/PROTOCOL_v3.md` (commit `9f1b586`) and the single frozen confirmatory run (`v3-confirmatory-001`, `FREEZE_v3.md` 7/7 SHA-256 match = YES) is recorded below and mirrored in the paper's **Protocol Deviations** table.

| # | Area | Pre-Registered in `PROTOCOL_v3.md` | Actual in `v3-confirmatory-001` | Rationale & Impact |
|---|---|---|---|---|
| **D1** | **Corpus 1 Query Disjointness & Dev-Split Exclusion** | Full `522,931` BEIR Quora; confirmatory test queries sampled strictly from `[500..9,984]`. | Enforced programmatically in `bench/dataset_v3.py:load_corpus_v3("quora")` (`Q_all[500:]`, `9,485` queries, `0` ID/text overlap with corpus, `0` overlap with Phase 17 dev queries `[0..499]`). | Zero dev-to-test leakage; matches protocol strictly. |
| **D2** | **Corpus 2 Selection & Encoder** | Distinct-domain real BEIR Wikipedia corpus (`BeIR/nq` or `BeIR/hotpotqa`, `N=250,000`), `all-MiniLM-L6-v2` (384-d) or `bge-base-en-v1.5` (768-d) if cached locally. | Used `BeIR/nq` (Wikipedia QA, first `250,000` passages, `3,452` strictly disjoint test queries, `0` ID/text overlap) encoded with locally cached `sentence-transformers/all-MiniLM-L6-v2` (384-d, MPS; `bge-base-en-v1.5` not present in local cache). | Provides cross-domain generalization (long Wikipedia passages vs. short Quora questions) on identical 384-d embedding dimensionality. |
| **D3** | **Upstream `ACORN-gamma` Parameters & RAM Accounting** | Upstream C++ `acorn-gamma` with $\gamma = 4$ or $\gamma = 10$; verify $\le 0.5\times$ extra RAM vs. `v3-geom-M8`. | Ran compiled upstream C++ `stanford-futuredata/ACORN` (`c259f11cdbec` + 3-line OOB memory-safety patch) with $\gamma = 4, M_\beta = 64$ (`efConstruction=64, efSearch=64`) on both corpora (`~18s` at 100k, `~100s` at 523k; $\gamma=10$ exceeds 10 min/seed budget). Upstream `ACORN.cpp:167` allocates `M_beta + 1.5*M = 88` level-0 edges/node (`+224 B/node` extra level-0 RAM over base `M=16` HNSW `32` edges, excluding additional `4x` upper-layer edges), compared to `+32 B/node` (`M_bridge=8`) for `v3-geom-M8` (`0.143x` extra level-0 RAM). | Conservative lower bound on `ACORN-gamma`'s extra RAM (`224 B/node` ignores upper-layer bloat), so `0.143x <= 0.5x` holds conservatively. |
| **D4** | **Qdrant & HoneyBee Availability** | Include `Qdrant` if runnable natively without Docker; otherwise record in `DEVIATIONS.md`. | `qdrant` has no native Homebrew bottle and Docker daemon is unavailable; `HoneyBee` has no public source code. Neither is plotted (no Python mocks substituted). | Upholds ADR-0004 real-engine integrity rule. |
| **D5** | **v3 Module Preservation of Frozen v2** | Freeze v3 algorithm hashes in `FREEZE_v3.md` while keeping Milestone 4 v2 archived cleanly. | Placed v3 engine in `src/modules/prism_ann_v3/` + `bench/prism_ckernel.cpp` (`FREEZE_v3.md`, 7/7 SHA-256 verified), keeping `src/modules/prism_ann/` 100% untouched (`FREEZE.md` 5/5 SHA-256 still verified). | Preserves complete Milestone 4 & Milestone 5 provenance simultaneously. |
| **D6** | **Shared Base Graph Construction (`FAISS M=16`)** | `M = 16`, `efConstruction = 64`, `efSearch = 64` across all HNSW systems. | `GeometricHHNSW` extracts both upper-layer CSR and level-0 adjacency (`M_max0 = 32`) directly from the same `faiss.IndexHNSWFlat(384, 16, METRIC_INNER_PRODUCT)` instance evaluated as `faiss-hnsw-M16`, ensuring `H2v3`, `H3v3`, and `H5v3` share the exact base graph. | Eliminates the `M=8` vs. `M=16` base-graph confound from v2 and guarantees apples-to-apples 4-way portal ablation (`H5v3`). |
| **D7** | **`hnswlib` Python Filter Callback & `pgvector` Scope** | Real `hnswlib 0.8.0` and real PostgreSQL 17.12 + `pgvector 0.8.7` (`iterative_scan = relaxed_order`). | `hnswlib-M16` runs native C++ HNSW with a pybind11 Python mask callback (`C++/Py-cb`, explicitly labeled in tables). `pgvector-hnsw-iter` runs on **both** Corpus 1 (`523k` Quora) and Corpus 2 (`250k` BEIR NQ) in `H2v3` with `EXPLAIN`-verified HNSW index usage (`hnsw.max_scan_tuples=20000`, `enable_seqscan=off`), and in `H4v3` with a B-tree index on `folder_id` for transactional `UPDATE`. | Transparent latency framing for `hnswlib` FFI overhead and complete 2-corpus `pgvector` coverage. |
| **D8** | **Persistent PostgreSQL-Backed SpiceDB Coverage (`H1v3` & `H4v3`)** | Measure `H1v3` on both `--datastore-engine memory` and `--datastore-engine postgres`, and `H4v3` on `--datastore-engine postgres`. | Executed full `n = 600` principals (`200/seed x 3 seeds`) on **both** memory AND persistent PostgreSQL 17 SpiceDB (`spicedb migrate head` + `synchronous_commit=on`) in `H1v3`, and `n = 5` trials on persistent PostgreSQL 17 SpiceDB in `H4v3`. | Zero sample-size reduction; full durability on real PostgreSQL 17. |
