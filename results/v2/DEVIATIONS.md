# Protocol Deviations from `experiments/v2/PROTOCOL_v2.md` (ADR-0004)

Every deviation between the pre-registered protocol (`experiments/v2/PROTOCOL_v2.md`, commit `3dbf7ed`) and the single frozen confirmatory run (`v2-confirmatory-002`, commit `c819e65`, `freeze_match = YES`) is recorded below and mirrored in the paper's **Protocol Deviations** table.

| # | Area | Pre-Registered in `PROTOCOL_v2.md` | Actual in `v2-confirmatory-002` | Rationale & Impact |
|---|---|---|---|---|
| **D1** | **Corpus Download Mirror & Duplicate-Text Filter** | Download BEIR Quora from `public.ukp.informatik.tu-darmstadt.de/.../quora.zip`; held-out BEIR Quora test queries never inserted into corpus. | `public.ukp.informatik.tu-darmstadt.de` failed DNS resolution; fetched official `BeIR/quora` (`522,931` passages) + `BeIR/quora-qrels` (`10,000` test query IDs) from HuggingFace mirror (`BeIR/quora`). Removed `15` test queries whose exact text string appeared in `corpus.parquet`, leaving `9,985` strictly disjoint held-out queries (`0` ID overlap, `0` exact text overlap). | Identical official BEIR Quora dataset; stricter leakage hygiene (0 exact-text query duplicates). Full `N = 522,931` corpus used with zero subsampling. |
| **D2** | **Prism Base Graph Construction Adapter** | Explicitly authorized engineering deviation: *"Base graph construction may be delegated to FAISS HNSW for scale... the traversal algorithm is unchanged."* | `bench/systems.py:build_prism_bundle` constructs the level-0 base graph (degree 16) via `faiss.IndexHNSWFlat(384, 8, METRIC_INNER_PRODUCT)` (`efConstruction=64`) and populates frozen `AncestorStitchedHNSW` in memory without modifying any file in `src/modules/prism_ann/` (`FREEZE.md` match = 100%). Express bridges ($M_{\text{bridge}}=4$) use the frozen `_medoid_ring_and_chord` method. | Scales Prism graph construction to `N=522,931` (~20 s/seed) while preserving frozen traversal verbatim. `faiss-hnsw-M8` provides a shared-graph secondary baseline; `faiss-hnsw-M16` (level-0 degree 32) remains the primary FAISS baseline per `bench/verdicts.py`. |
| **D3** | **Chunks per Document (`L=4, b=8` vs. `H4`)** | `L=4, b=8` tree with passages grouped into docs of `~150` chunks; `H4` revokes one folder edge covering `>= 1,000` docs (`~150k` chunks). | In `H1`–`H3`, `8^4 = 4,096` leaf docs partition all `522,931` passages into `127.7` chunks/doc (exact balanced `b=8, L=4` tree). In `H4`, a 3-level tree places `1,024` docs × `150` chunks/doc = `153,600` chunks under one revocable container edge (`node_L0_0 -> node_L1_0`) and the remaining `369,331` chunks under `node_L1_1`. | Satisfies `L=4, b=8` exactly on full `N=522,931` in `H1`–`H3`, and satisfies `>= 1,000` docs and `~150k` chunks (`153,600`) exactly in `H4`. |
| **D4** | **H1 Bitmap Engine (`pyroaring` CRoaring)** | Measure median UBP + bitmap build vs. SpiceDB `LookupResources` streaming + leaf bitmap build. | Used native C++ CRoaring (`pyroaring 1.2.0` with `.run_optimize()`) symmetrically for both UBP and SpiceDB leaf bitmap unions, and also reported the stricter `SpiceDB-ReadRelationships+UBP+bitmap` variant that fetches grants/denies live from SpiceDB over gRPC. | Eliminates pure-Python loop noise from both sides so `P1c` compares real C++ Roaring bitmaps against real SpiceDB gRPC; strict variant proves the `>=10x` speedup holds (`33.6x`) even without a local grant cache. |
| **D5** | **Upstream `stanford-futuredata/ACORN` (`ACORN-1`) Build & C++ Safety Patch** | Use FAISS ACORN if present in wheel; otherwise mark `P2b` untestable. | `faiss-cpu 1.16.0` lacks `IndexACORNFlat`. Built official upstream C++ `stanford-futuredata/ACORN` (`commit c259f11cdbec`) natively on macOS arm64, wrapped via `bench/acorn_cwrap.cpp` (`ctypes`). Used `METRIC_L2` (rank-identical to cosine/IP on unit vectors), `SearchParametersACORN::sel` (`FilterMapSelector`) to block an upstream entry-point authorization leak (`ACORN.cpp:1226`), `acorn.efSearch = 64` (`ACORN.cpp:1547`), `acorn_stats.n3 + 1` for exact distance counts, and a 3-line C++ memory-safety patch (`ACORN.cpp:1061` `ep_per_level(max_level+1)` off-by-one heap overwrite; lines 757/829 bounds check before `metadata[nodeId]`; 0 algorithmic changes). | Makes `P2b` **testable** against the authors' actual C++ `ACORN-1` implementation instead of marking it untestable, with 0 algorithmic changes and 0 leaks. |
| **D6** | **pgvector 0.8.7 Configuration & Scope** | Real PostgreSQL + pgvector 0.8 iterative scan (`SET hnsw.iterative_scan = relaxed_order;`) in `H2` and ACL `UPDATE` in `H4`. | Ran native Homebrew PostgreSQL 17.12 + `pgvector 0.8.7` (`m=16, ef_construction=64, hnsw.ef_search=64, hnsw.iterative_scan=relaxed_order`, default `hnsw.max_scan_tuples=20000`, `enable_seqscan=off` with verified `EXPLAIN` confirming HNSW index scan) across all 3 seeds in `H2`, and 5 trials in `H4` (with B-tree index on `folder_id` so `UPDATE` targets only the `153,600` revoked rows). `H3` omits `pgvector` per `PROTOCOL_v2.md`. | Guarantees `pgvector` genuinely exercises iterative HNSW scan in `H2` and indexed transactional `UPDATE` in `H4`. |
| **D7** | **Missing Non-Public Baselines (`HoneyBee`)** | Per `ADR-0004`: systems with no public implementation are discussed, not plotted as measured baselines. | `HoneyBee` (no public source) is discussed in Related Work / Taxonomy only and excluded from v2 plots and tables. | Avoids home-made baseline reimplementations (the core v1 defect). |
| **D8** | **Pre-Registered Verdict Aggregators (`bench/verdicts.py`)** | `PROTOCOL_v2.md` defines `P1a`–`P4b` criteria; `bench/verdicts.py` (committed in Phase 13 before any v2 run) locks exact aggregation rules. | Across-seed means of per-seed means + paired 95% $t$-intervals for `P2`/`P3`; pooled medians for `P1c`; `P2a`/`P2c` required at every $S \le 0.5\%$; `P2b` required at every $S$ in the sweep; median over 5 trials for `P4b`. | Fixed prior to confirmatory execution; recomputed deterministically from raw JSONL records. |
| **D9** | **Implementation Language Asymmetry (Secondary Latency Metric)** | Per `ADR-0004`: Recall@10 and distance computations are primary hardware-independent metrics; latency is secondary with language noted. | `Prism-ANN` traversal (`src/modules/prism_ann/hnsw_gls.py`) runs in Python/NumPy; `FAISS`, `ACORN-1`, `hnswlib` (graph core, Python filter callback), and `pgvector` run in C/C++. | Latency is never headlined as a language-normalized algorithmic speedup for graph traversal; hardware-independent Recall@10 and distance computations lead. |
